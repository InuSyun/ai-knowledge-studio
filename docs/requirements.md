# AI Knowledge Studio 要件定義

## 目的と利用者
- 技術書・論文・学習メモから抜き出した文章を短く、または詳しく要約し、内容の理解を助ける。初期利用者は開発者本人で、技術資料を読むときに使う。公開版はデモとして提示する。

## 利用シナリオ
- 正常時　文章を貼り付ける → 要約モードを選ぶ → 「分析する」を押す → 処理中の表示を見る → 要約とProvider種別を確認する。
- 入力エラー時　空欄で「分析する」を押すと、「要約する文章を入力してください」と表示される。
- 公開デモ　結果のそばに「これはデモ応答であり、AIが生成した要約ではありません」と表示される。

## 機能要件と受け入れ基準
| ID | 機能要件 | 受け入れ基準 |
|---|---|---|
| FR-01 | 利用者は文章を入力欄に貼り付け、編集できる。 | 「Reactを学ぶ」を貼り付けて「FastAPIを学ぶ」に編集すると、入力欄に「FastAPIを学ぶ」と表示される。 |
| FR-02 | 利用者は`short` / `detailed` の2種類を選べる。 | 「短い要約」を選んで送信すると mode: "short"、「詳しい要約」なら mode: "detailed" が送られる |
| FR-03 | 	要約APIは、受け取った本文とモードに基づいて設定済みのLLM Providerに処理を依頼し、結果を返す。 | Mock Providerを使い、有効な本文と short を POST /api/v1/summaries に送る。詳しい要約を依頼するときは mode に「detailed」を指定して送る。APIが 200 を返し、応答の mode が「detailed」になっていることを確認する。 |
| FR-04 | 成功時に要約とProvider種別を画面表示できる | APIが provider: "ollama" を返したとき、画面に summary の本文と『Ollama』が表示される。`provider: "mock"` を返したとき、本文と『Mock（デモ）』、デモの案内文が表示される。 |
| FR-05 | APIは前後の空白を除いた本文が1〜5,000文字で、モードが `short` または `detailed` の場合に入力を受け付ける。 | Mockを使ったAPIテストで、有効なモードと前後に空白を付けた本文5,000文字を送ると `200`。空文字、空白のみ、本文5,001文字、不正なモードはそれぞれ `422`。 異常条件を一つずつ変えて確認する。空欄で『分析する』を押すと『要約する文章を入力してください』と表示され、APIにリクエストを送らない|
| FR-06 | 要約に失敗した場合、画面に原因に応じた案内を表示する。 | ①ブラウザからAPIに接続できないときは「サーバーに接続できません」と表示する。②LLMとの接続障害や不正な応答でAPIが 502 を返したときは「要約処理に失敗しました」と表示する。③LLMが制限時間内に応答せずAPIが 504 を返したときは「要約に時間がかかりすぎました」と表示する。各ケースを個別に確認する。|
| FR-07 | 実行中の表示と多重送信防止を備える。 | 要約の応答を待っている間、画面に「要約中」が表示される。 応答待ちの間に『分析する』を続けて押しても、要約リクエストは1件だけ送られる。|
| FR-08 | GET /health でAPIプロセスの応答を確認できる。 | APIを起動し、`GET /health` を送ると 200 と {"status":"ok"} が返る。|

## 非機能要件
- 入力した原文を保存せず、ログにも記録しない。
  - 確認方法：アプリのコードに原文を保存する処理がないことを確認する。サンプル文章で要約を実行し、ログに入力した原文が出力されていないことを確認する。

## 完成条件
- ローカル版では、実際のLLMにサンプル文章を送り、入力内容に沿った要約が返ることを少なくとも1回確認する。
- 公開デモ版では、ProviderをMockに固定する。公開画面から要約を実行し、結果とデモの案内文が表示されることを確認する。

## 今回の対象外
- PDF読込、RAG、認証、DB、チャット履歴、AIエージェント、多言語対応、Kubernetes、複雑なUIは対象外
